# Luciole v1.5 · 帷幕期

上帝视角剧本引擎：把玩家从编剧席送回角色席。

Luciole 把完整真相留在隐藏账本里；运行时的 God 只能裁定 ID 与枚举，演员只收到插件本地从安全库装配的当轮表现包。秘密是否能推进由因果资格与节奏下限共同决定，而不是让主模型一看见故事脉络就直奔结局。

## 安装

把 `luciole` 文件夹放到：

`SillyTavern/data/default-user/extensions/luciole/`

然后重启 SillyTavern。也可以把本目录放入 Git 仓库，通过扩展面板的 Install extension 安装。

从 v1.4 升级前建议先备份酒馆数据。v1.5 会把旧线放入迁移隔离区；旧结构不会继续向演员注入。

## 第一次点灯

1. 在角色卡、用户人设和可读世界书中移除秘密答案，只留公开表层。
2. 打开 Luciole 面板，配置 God 航道：跟随酒馆当前连接，或使用独立 OpenAI 兼容 API。
3. 填写线名、完整秘密、节奏档与玩法，点击“让 God 编译”。
4. 作者模式中逐条检查编译 JSON 与安检结果；确认后真相与安全库一起锁定。
5. 运行时只有一条线处于 FOCUS，其余线仍是受保护的 STANDBY。

编译结果不合格时不会入库。稳定指纹、最早披露档位、probe 结构、阶段条件、人物安全画像和线索许可集都经过本地硬校验。

## 两种玩法

- **作者模式**：可以查看隐藏账本、修改编译草稿，并在探针无法确定时使用“确实交付 / 未交付撤销 / 稍后”三键仲裁。
- **盲玩模式**：激活后，面板不展示未交付 surface、claims 或隐藏账本；连续两次漏演会自动撤销本次授权并等待重排。

盲玩模式只是运行期遮幕，不等于自动建局盲。若秘密由玩家本人输入，玩家当然已经知道它；真正的玩家盲局需要后续私人副本引擎或由主持人预先编译的内容包。

## 运行规则

- 每个聊天最多四条受保护线，同一时刻最多一个焦点、每轮最多一次披露。
- God 只在节奏到点、公开唤醒词命中、本地条件变化或手动召唤时运行。
- God 没有散文通道，只能从已编译的 `clue_id / variant_id / release_policy` 白名单选择。
- 演员表现包包含：当前演法、公开锚点、人物行为、本轮披露许可、知识边界；总注入有硬预算，任何安全字符串都不会被半截截断。
- 裁定先冻结，正文成功且探针确认交付后才整包提交。阶段、压力、条件、披露与人物行为冷却同进同退。
- 同楼重抽沿用原裁定，不会把 swipe 变成命运老虎机；TTL 四轮到期会撤销未交付授权。
- 尾部删楼和最新一楼重抽可自动整包回滚；编辑旧消息或更早历史分叉会回滚到分叉点，并提示从当前世界重新推进。

## v1.4 迁移

旧耕田碎片与编剧脉络只作为新编译材料，不会直通运行期。迁移预览会逐条列出旧版已经放出的光：

- `state=2` 的旧版已落地内容默认勾选；
- `state=1` 的“已放、尚未核实”默认不勾，避免把漏演误写成事实；
- 每项由作者确认 fact / motive / emotion 层后，才作为 revision 0 的只读迁移基线写入；
- 超过 200 字的旧光不会被截断，也不会直接进入基线，仍会保留在编译材料中。

## 已知边界

- 指纹安检是确定性近似，能挡稳定专名和短语，不能证明语义绝对无泄漏；作者模式的最终预览仍是必要防线。
- 插件会核查当前可读的角色卡字段、用户人设和世界书对象。旧聊天正文、预设文本以及其他插件的私有注入不可达；秘线建议在新聊天启用。
- v1.5 不做多线批处理，也不自动重建更早历史分叉后的全部裁定。
- “跟随酒馆当前连接”依赖当前连接支持 `generateQuietPrompt`；不支持时请配置独立 API。
- 独立 API Key 明文保存在 SillyTavern 扩展设置中，共用设备请自行留意。

## 开发验收

主程序保持 ES5 语法，不修改全局原型。仓库内的核心验收可用 Node 运行：

```bash
node --check index.js
node --test tests/core.test.js
```

测试覆盖冻结规格的 F1–F21，包括许可扫描、语义槽探针、严格 God Schema、越闸边界、原子提交、盲玩漏演、TTL、整包 inverse diff、最新 swipe 恢复、旧版隔离与 false-memory 边界。
