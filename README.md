# Luciole v1.6.6 · 三轨播种

上帝视角故事引擎：把玩家从编剧席送回角色席。

Luciole 把真相留在隐藏账本里，只把当前获准的一程光交给演员。玩家仍然决定自己做什么，但不必提前知道故事终点，也不用替 AI 安排下一幕。

### v1.6.6 · 酒馆连接配置真流式

强模型在后台思考超过约 60 秒时，“跟随酒馆当前连接”的 raw / quiet 调用可能尚未返回正文，就先被云酒馆门口的反向代理切成 `504`。单纯把 Luciole 的客户端等待时间改长，不能延长反代的等待时间。

v1.6.6 新增第三种模型航道“连接配置 · 真流式”：

- 直接使用酒馆官方 `ConnectionManagerRequestService`，按你在“连接管理器”里保存的 Connection Profile 发起请求；
- `stream: true` 从模型思考阶段开始逐块接收，插件在本地拼回完整 JSON；思考内容只用于保持连接与诊断，不会交给演员；
- 编译仍保留分段步骤与草稿检查点，每完成一步立即保存，中断后只重试失败步骤；
- 如果某条配置没有真正交出流式生成器，Luciole 会明确报“没有真流式”，不会偷偷改走整包请求，也不会自动发起第二次收费调用；
- 编译连接测试给强模型最多 120 秒和 256 个输出 token，避免推理 token 把“通”挤没；正式编译仍使用 500 秒总闸；
- 同一个安装包按能力探测工作，不提高最低版本：SillyTavern 1.14–1.18 均可使用；服务不存在、连接管理器被停用或配置不受支持时，面板会说明原因，原有“当前连接 · 兼容”和“独立 API”仍可选；
- SillyTavern 1.18+ 能按 Connection Profile 携带其中保存的 `secret-id`。1.14–1.17 的真流式服务可能沿用对应提供商当前选中的密钥，面板会提示先测试；Luciole 本身不读取酒馆密钥。

升级不会改写旧设置。原本选择“跟随酒馆”的用户仍停在兼容航道，只有主动选择“连接配置 · 真流式”并指定配置后才切换。

### v1.6.5 · 当前连接兼容航道

部分酒馆当前连接会在 `generateRaw + jsonSchema` 请求进入模型前直接返回 `Bad Request` 或 `Service Unavailable`。v1.6.5 不再向兼容航道发送原生 Schema 参数：

- JSON Schema 仍完整写在每个短步骤的固定提示中，并由插件本地逐字段验收；取消的是上游不兼容的请求参数，不是安全契约；
- 正式编译先尝试不带 Schema 的 `generateRaw`，保持无聊天上下文的干净输入；
- 若 raw 航道发生请求级拒绝，立即自动切到 `generateQuietPrompt` 短步骤；本页会话的后续步骤与断点续跑直接沿用兼容航道，不再反复撞 raw；
- “测试编译航道”与正式编译现在走完全相同的路线；诊断台会明确显示“原始短调用”或“原始航道被拒后自动切换”；
- v1.6.4 的失败草稿可以原地续跑，已经成功保存的步骤不会重做。

若 raw 的首次请求被拒后 quiet 兼容调用成功，本次只会多一次未进入正文生成的失败请求；插件不会对已收到正文的调用做静默重试。

### v1.6.4 · 酒馆当前连接分段编译

针对“跟随酒馆当前连接”在强模型上等待约 50 秒后只得到空内容、截断文本或不完整 JSON 的情况：

- 编译优先使用酒馆官方 `generateRaw`，不再携带旧聊天正文与角色扮演上下文；不兼容时由 v1.6.5 的兼容航道接管；
- 每个短步骤的提示词都携带严格 JSON Schema，回包继续由插件本地解析和校验；
- 一次大编译拆成“真相命题 → 因果结构 → 安全外壳 → 内容小批”；智能调度每批最多 8 条候选，均匀散落每批最多 25 条种子；
- 每完成一步立即落入聊天草稿。中途断网、刷新或回包不完整后，点“继续编译”只重跑失败步骤，不重收已经完成的步骤；
- v1.6.3 留下的 `0 / 1` 空失败草稿会自动升级成分段检查点，不用重新填写表单；
- 报错台会显示实际调用路线，草稿进度统一显示为“步骤”。

跟随酒馆当前连接会以多次短调用换取可续跑与完整回包：AI监督通常 4 次；智能调度为 `3 + 向上取整(候选数 ÷ 8)` 次；均匀散落为 `3 + 向上取整(线索数 ÷ 25)` 次。独立 API 仍走 v1.6.3 的 SSE 流式航道，不改成这套多步调用。

### v1.6.3 · 流式编译与草稿续传

针对强模型编译时首包慢、JSON 大而触发 `504 Gateway Timeout` 的情况：

- 独立 OpenAI 兼容 API 的所有编译调用默认使用 `stream: true`，插件持续读取 SSE 数据块并在本地拼回完整 JSON；
- 编译总闸独立为 500 秒，运行期仍是 20 秒；独立 API 编译请求的 `max_tokens` 明确不少于 8000；
- 诊断台会记录流式/整包传输、收到响应头、首个数据块、总耗时与中断前字节数；
- 每个完整批次一通过结构检查就立即写入聊天草稿，状态为 compiling / partial / ready / failed；
- 刷新页面或后续批次断网后，可用“草稿检查点”继续；已经完成的批次不会重新收费生成；
- 长编译任务绑定发起它的聊天；途中切换聊天，草稿与最终结果仍只写回原聊天；
- 不会在流式失败后静默发起第二次普通请求，避免同一次编译重复计费。

客户端等待 500 秒不能改写中转站自身的绝对超时。如果网关在第一块流数据出现前就主动返回 504，面板会如实显示；当前批需要手动重试。跟随酒馆当前连接没有底层 SSE 读取钩子，因此从 v1.6.4 起使用短步骤与逐步检查点处理。

### v1.6.1 · 编译台创作权限

编译台现在以“受约束的谜局设计师”工作，而不是把秘密压缩成几句摘要：

- 核心真相、既定动机、玩家选择和角色卡约束仍然锁死；
- 可以在不冲突的空白处设计记录、票据、时间差、物理痕迹、流程异常、通讯残片、旁观者片段、误判与传闻；
- 同一条真相可以拥有多条不同场景、载体和视角的证据路径；
- `candidate_target` 是候选线索数，不是秘密命题数，编译模型必须精确交齐；
- 秘密指纹必须排除角色卡与用户人设中本来就公开的人名、职业、关系、地点和常用物件，减少误报。

创造权只用于丰富“怎样发现”，无权改写“真相是什么”。

### v1.6.2 · 连接与报错台

God 双航道下方新增常驻诊断窗口：

- 可分别测试“编译航道”和“运行航道”，也可在保存方案前测试当前填写；
- 连接中、成功、安检拦截、HTTP 错误、空回包、输出截断、超时和运行期拒收都会留在面板里；
- 显示调用航道、模型、脱敏后的目标地址、时间与耗时，最近保留 20 条，直到用户手动清空；
- `400 / 401 / 403 / 404 / 429 / 5xx` 会翻译成可操作的人话，上游原始说明放在折叠详情中；
- API Key、Bearer 凭据与 URL 查询令牌会在写入记录前清除；盲玩模式不会把未来内容写进报错详情。

短暂 toast 仍作为即时提醒，但不再承担唯一报错入口。

## 安装

把整个 `luciole` 文件夹放到：

`SillyTavern/data/default-user/extensions/luciole/`

然后重启 SillyTavern。也可以把 `luciole` 文件夹原样上传到 GitHub，再从 SillyTavern 的扩展安装入口使用仓库地址安装。

运行插件只需要这四项：

- `manifest.json`
- `index.js`
- `style.css`
- `README.md`

`tests/` 不参与日常运行，但建议一并上传，方便以后升级时确认旧能力没有坏。

## 三种运行方式

### AI 监督 · 随境生光

适合不想预设故事终点、希望线索跟着剧情自然生长的长线 RP。

- 你只设置“每隔几轮监督一次”和线索力度；
- 编译台只建立真相骨架，不预写全部线索；
- 每到监督窗口，守幕人读取近期剧情和有限真值切片，决定 hold、推进或临场起草一条证据；
- 运行期间会调用模型；默认每个间隔至多一次；
- 安全标记为“动态候选级”：临时证据仍要过 Schema、命题许可、阶段、性质和指纹安检，但不能宣称语义上绝对无泄漏。

### 智能调度 · 循迹择光（推荐）

适合“前期愿意用强模型，之后想用便宜模型慢慢玩”。

- 你设置预计总轮数、调度间隔和线索力度；
- 强编译模型提前建立完整候选库；
- 运行时模型只从合法 `clue_id / variant_id` 中选牌，不能临场写新线索；
- 编译模型和运行模型可以分开：例如编译使用强模型，调度使用便宜的轻量模型；
- 面板会用人话显示候选库“剩余 N 条 / 共 N 条”；快用完时可点“补充候选”，确认后由编译模型新增 1–40 条，旧真相、旧候选和历史账本保持锁定；
- 安全标记为“封闭白名单级”。

例：预计玩 500 轮、每 10 轮调度一次，预计有 50 个窗口。Luciole 会要求约 60 条候选，额外部分用于场景不合适时换牌。

### 均匀散落 · 星雨成行

适合节奏必须可计算、运行时希望完全不再花 God 调用的钱。

- 你设置预计总轮数、投放间隔和线索力度；
- 线索数 = `floor(预计总轮数 / 投放间隔)`；
- 编译台开局拆好有序线索；独立 API 每批最多 100 条，跟随酒馆当前连接每个内容步骤最多 25 条；全部步骤通过后才会一起激活；
- 运行时严格按顺序本地投放，God 调用数恒为 0；
- 某条漏演时不会跳到下一条，真正交付后下一投放点会滑动顺延；
- 安全标记为“封闭白名单级”。

例：预计玩 500 轮、每 5 轮一条，会拆成 100 条线索；第 5、10、15……轮依次投放。

## 什么叫“一轮”

一次玩家行动加一次角色回复，算 1 个完整 RP 轮。

- 激活 Luciole 之前的聊天历史不计入新线的轮数；
- 同一楼 swipe / 重抽不增加轮数；
- 生成失败不增加轮数；
- 删除楼层时，轮时钟、已交付线索、阶段和均匀游标会随事务一起回滚。

## 线索力度

- **轻柔留痕**：每次最多携带 1 个已经合资格的信息单元，只用观察或传闻；
- **标准推进**：每次最多 2 个信息单元；
- **清晰证据**：每次最多 3 个信息单元，条件成熟后可以出现事实或陈述。

力度只控制本轮信息密度，不能越过命题最早阶段、因果条件、洋葱层或越闸上限。选择“清晰证据”不会让第 10 轮直接得到第 500 轮的动机结局。

## 公开关键词怎样触发

编译台会从公开表层提取一组 `wake_aliases`，例如已经公开的人名、地点或话题。它们不是秘密答案，也不是“说中一个词就掉线索”的机械机关。

默认行为：

- 只扫描玩家刚发出的新消息，不扫描演员自己的回复；
- 命中后只记一个本地“值得留意”标记，等下一个正常监督/调度窗口参考；
- 不会因此偷偷多调用一次 API。

若你手动开启“事件唤醒”：

- 玩家命中公开话题时，可以把下一次 AI 监督或智能调度提前；
- 提前调用后，原来的时间点不会再重复调用；下一窗口从本次重新按间隔计算；
- 均匀散落永远不会因关键词调用模型。它只会保留“催促剧情”入口。

## God 双航道

面板里可分别设置：

- **编译模型**：负责拆真相、写候选或种子，建议用能力较强的模型；
- **运行模型**：只在 AI 监督和智能调度中使用。可跟随编译模型，也可单独选择另一份酒馆连接配置、当前连接兼容航道或独立轻量 API。

三种航道的区别：

- **连接配置 · 真流式（推荐给强编译模型）**：从酒馆“连接管理器”读取配置，由酒馆代发并持续回流；支持 Chat Completion 与 Text Completion 配置；
- **当前连接 · 兼容**：优先使用 `generateRaw`，遭遇请求级不兼容时改用带明确数据边界的 `generateQuietPrompt`；这两种后台调用都不是可读取的真流式，云端 60 秒反代仍可能切断强模型；
- **独立 API**：Luciole 自己保存地址、模型名和 Key，直接调用 OpenAI 兼容 `/chat/completions`；编译请求使用 SSE 流式。

固定 system 规则与 JSON data payload 始终分开发送。Connection Profile 和独立 API 都不会携带旧聊天正文；当前连接兼容航道的 quiet 回退会经过酒馆上下文调用，但资料被 BEGIN/END 数据边界包住。

运行期调用设有 20 秒总闸：超时就安全 hold、立即放行正文；迟到回包永久丢弃，不能在玩家已经看到正文后补写幽灵命运。插件不会在失败后静默追加收费调用。

## 第一次点灯

1. 在角色卡、用户人设和可读世界书中移除秘密答案，只保留公开表层。
2. 打开 Luciole，先配置编译模型。强模型优先选“连接配置 · 真流式”：先在酒馆连接管理器建好配置，再回 Luciole 下拉选择并点“测试编译航道”；智能调度或 AI 监督再配置运行模型。
3. 填线名、完整秘密，选择作者/盲玩、三种运行方式、轮数、间隔和力度。
4. 点击“让 God 编译”。
5. 普通界面只显示人话，例如“已拆分线索 100 条”；作者可以展开人话线索预览。JSON 放在折叠的“开发者详情”里。
6. 若安检未过，页面先说明“哪类问题需要修”；`clue / claim / stage / probe` 等技术原因只在作者模式的折叠栏里。
7. 安检通过后点击“确认并锁定”。

每个聊天最多四条受保护线；同一时刻只有一条 FOCUS 负责推进，其余 STANDBY 仍穿知识边界，不会因为不推进就裸奔。

## 作者模式与盲玩模式

- **作者模式**：可以预览未来结构、展开开发者 JSON，并在探针拿不准时使用“确实交付 / 未交付撤销 / 稍后”三键仲裁。
- **盲玩模式**：只显示“拆分线索 N 条”、当前轮数、下一处理点和已经公开的账本；未来 surface、claims 和技术详情都不出现。

盲玩模式只是不在运行面板剧透。如果秘密本来就是玩家本人输入的，玩家当然已经知道它；真正的完全盲局需要主持人预编译内容包，或后续私人副本引擎。

## 事务与回滚

- 裁定先冻结，演员演出并由探针确认后，阶段、条件、披露、人物行为冷却与均匀游标才原子提交；
- 漏演不入账；同楼 swipe 沿用同一裁定，不会变成命运老虎机；
- 尾删和最新一楼重抽会自动整包回滚；
- 编辑更早历史时，Luciole 回滚到最早分叉点并提示重新推进；
- 事件流水只追加，回滚也是一笔新事务，不偷偷改写历史。

## v1.4 / v1.5 升级

- v1.5 的帷幕线会原地迁移成“智能调度”，保留 hidden/safe/control/runtime 四区、pending、谱系和事件流水；旧 `min_gap` 暂时沿用，面板标注“沿用旧版节奏”。
- v1.4 数据继续进入迁移隔离区，必须逐条重新编译和确认，旧结构不会直接向演员注入。

升级前仍建议备份 SillyTavern 数据。

## 已知边界

- 指纹安检是确定性近似，能挡稳定专名和词组，不能数学证明不存在语义暗示；AI 监督尤其需要诚实理解为“动态候选级”。
- 插件只能核查它可读到的角色卡、用户人设和世界书对象；旧聊天正文、预设私有注入和其他插件不可读通道无法被完全扫描。建议在新聊天启用秘密线。
- 均匀散落不做运行期语义理解。若硬证据突然拍脸，请使用“催促剧情”提前下一条；作者模式还可做事实层仲裁，但不会顺带打开动机与情感层。
- 单条秘密目前最多 2000 字；均匀序列最多 1000 条；智能调度候选库总量最多 160 条，单次补库最多 40 条。
- Connection Profile 真流式依赖上游与中转站真的保留 SSE；若中转站先缓存完整内容再吐回，Luciole 会在测试台显示没有及时收到数据块，反代仍可能 504。
- SillyTavern 1.14–1.17 可能不把 Connection Profile 的 `secret-id` 传给扩展请求；请保证对应提供商当前密钥可用并先点“测试编译航道”。1.18+ 才能稳定按配置密钥标识代发。
- 独立 API Key 保存在 SillyTavern 扩展设置中，共用设备请自行留意。

## 开发验收

主程序保持 ES5 语法，不修改全局原型。运行：

```bash
node --check index.js
```
