# Luciole 2.0 —— 小萤火 · 帷幕沙漏

> clean-room 重构 · 三模式全交付 · v2.6.2
> 施工：Claude Fable 5 · 2026-08-14

## 这一版是什么

把 v1.6.x 的 9054 行推翻重写为约 2100 行（三模式全含）。只保留一个承诺，并把它做到可靠：

**藏住真相，在正确的一次角色回复里，送出一束刚刚好的光。**

- 编译期：强模型读你的隐藏脉络 + 角色卡 + 角色主/内嵌世界书 + 最近正文（40条/8000字窗口），生成衔接现场、从浅到深的线索序列
- 运行期：**零 API 调用**，纯本地轮钟，到点注入、演完退场
- 没有 pending 锁、没有探针、没有事务机、没有迁移补丁

## 安装

把 `luciole2` 文件夹放进：
`SillyTavern/data/<用户>/extensions/` 或 `public/scripts/extensions/third-party/`
刷新酒馆后，三个入口任选：
- **萤火虫浮标**：聊天区右下的呼吸光点，点击开关面板，可拖动，可停进避风塘
- **魔杖菜单**：「小萤火」一项
- **扩展设置**：「🕯 小萤火 2.0」小抽屉里的「打开面板」按钮（此处也可隐藏浮标）

面板是独立浮窗，不再嵌入扩展设置页——与其他扩展的版面彻底解耦，不会叠字。
顶部三个模式位：帷幕沙漏（可用）、星星点灯 / 迷雾森林（Phase 2/3 施工中，灰显示意，不是坏了）。

⚠ 与旧版 Luciole 不共存数据、不迁移数据。建议先停用旧版再启用本版。

## 五分钟上手

1. **④ 连接**：填独立 API（地址/密钥/模型名），点「测试连接」
2. **① 故事**：写隐藏脉络（越具体越好），设总轮数和间隔，点「编译」
3. **② 线索预览**：作者模式下逐条检查，可改可删
4. **③ 点亮**：点亮后你的**下一条消息**就是第一束光的机会
5. 正常玩。到点它自己来，面板一句人话告诉你现在在哪。

## 运行规则（一条线索的一生）

```
排队 → 到点上台（注入）→ 随下一次回复演出（重抽也带着它）→ 你再发言时退场
```

- 重抽不重复消费：一条线索服务一个"回复位"，含它的所有重抽
- 你连发消息时，台上线索原地等待，不浪费
- 删过楼？「回拨一轮」手动校正轮钟
- 切聊天再回来，现场自动还原

## 安全承诺（只承诺能本地严格证明的）

| 层 | 保证 | 验证方式 |
|---|---|---|
| 结构安全 | 完整秘密永不进入注入文本 | 注入器只读编译产物 |
| 白名单 | 只注入通过安检的候选 | 编辑线索也过安检 |
| 字面安检 | 禁词 / 残留宏 / 秘密原文≥12字连续重合 | 本地滑窗比对（抗空格逃逸） |

**不承诺**语义级绝对无泄漏——没有任何本地扫描能严格证明这一点，我们不假装能。

## 实机验收清单（发布前请在真机上逐项打勾）

在 iOS 酒馆 + 你的常用中转上：

- [ ] 编译一个 10 条线索的故事（观察分批进度与日志）
- [ ] 编译中途杀掉网络 → 再点编译 → 确认从断点续跑
- [ ] 点亮后发第一条消息 → AI 回复里出现第一条线索的影子
- [ ] 对同一条回复重抽 2 次 → 面板显示同一条线索仍在台上
- [ ] 再发言 → 面板显示该线索退场、游标 +1
- [ ] 连发两条消息（中间不等回复）→ 线索不被吞
- [ ] 切到别的聊天再切回 → 状态正确还原、别的聊天无注入残留
- [ ] 熄灭 → 点亮 → 进度保留
- [ ] 全部送完 → 状态变为"送完"，继续聊天无任何注入
- [ ] 日志里每一条都是人话，没有工程术语

## v2.5.2 修复（2026-08-14 · 五哥审 + 落地）

- **串场守卫**：编译与调度都是跨网络的长操作，中途切聊天曾会把结果写进错的聊天（AI 监督模式最严重：A 的秘密生成的指示会被注入 B）。现在起飞时记下聊天身份，落地对不上就整份作废。取不到聊天身份的老酒馆版本会自动降级为不守卫，行为与旧版一致，绝不误杀编译——启动日志会明说守卫有没有生效。
- **编译中断保护**：编译期间切聊天不再静默丢结果，会明确报「本次作废」，草稿仍留在原聊天可续跑。
- **改线索不再被推平**：作者模式下正在改某条线索时，AI 回复/重抽不会再重建列表抹掉你的输入；失焦后自动补渲染。
- **调度失败不再被重抽反复触发**：一轮里调度员/God 出错后记为「本轮已试过」，下一轮再问，不会每重抽一次就重打一次接口。
- **结束语更诚实**：被剧情越过而废弃的线索不再被算作「已送完」，日志分开报送出数与废弃数。

## AI 监督（v2.2.0）

「真相先锁，God 现场设计这一程光。」

- **无需编译**：写好隐藏脉络直接点亮
- 每到间隔轮，God（调度员/God 连接位，建议强模型）在两轮空档里读近期剧情 + 完整秘密，裁决：**HOLD 暂缓**（下一轮再问）或**现场设计一条 30~80 字舞台指示**
- God 有创作权，但**没有免检权**：设计稿必须过全部本地安检（禁词 / 宏 / 与秘密原文 12 字连续重合），拦下按暂缓处理并记日志
- God 设计的指示进入账本走完整簿记（上台 / 重抽复用 / 退役 / 现场还原），与编译线索一视同仁
- 连续暂缓 ≥3 轮会在日志提醒你检查秘密写法或调高力度
- 超时 / 出错 = 本轮不投、下一轮再问，故事永不被锁死

## 连接小贴士

- **DeepSeek 官网**：地址 `https://api.deepseek.com`，模型 `deepseek-chat`，max_tokens ≤ **8192**（填大了会被拒）
- 编译连接与调度员/God 连接都有「拉取模型」按钮：GET /v1/models 后点模型名输入框即可下拉选择，也支持手动输入（中转站友好）
- 「使用酒馆当前连接」是非流式备用航道，长编译容易被网关 504 掐断——报错里现在会直接给出自救指引

## 智能调度（v2.1.0）

一轮流水线设计：AI 回复落地后、你阅读打字的空档里，调度员（可配便宜快模型）读最近剧情，从未用候选的头 5 条里选最贴现场的一张；你下一条消息发出的瞬间，选好的牌**同步**注入——注入时序与均匀模式完全相同，物理安全。

- 调度员只有选牌权，没有创作权，也读不到完整秘密
- 解析不依赖 JSON：直接在回话里搜候选编号（随机串，零误匹配）
- 超时 / 胡话 / 预选失效 → 确定性回退为按顺序发牌，日志明说，**永不 hold 死故事**
- 调度员连接独立配置（④连接底部），三项留空即复用编译连接
