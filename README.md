# Luciole v1.6.26 · 断线救援

上帝视角故事引擎：把玩家从编剧席送回角色席。

Luciole 把真相留在隐藏账本里，只把当前获准的一程光交给演员。玩家仍然决定自己做什么，但不必提前知道故事终点，也不用替 AI 安排下一幕。

### v1.6.26 · 断线救援

**从思考通道捞回被丢掉的答案。** 推理型模型常把整份 JSON 写在思考通道里、正文 0 字节。插件本来就有「从思考里捞 JSON」的救援，但**只在流正常结束时才跑**；一旦上游中途掐断连接，已经收到的几千字节思考内容会被整个丢弃，本步白跑。现在出错路径上也会试同一次救援：捞得到完整 JSON 就当本步成功并继续，捞不到才按原样报错。救援成功时会在遥测里标记 `stream_interrupted`。

**「查看技术详情」不再秒合上。** 报错台重绘是整块换 `innerHTML`，展开的详情框会被连根拔掉重建。现在每条记录带稳定 id，重绘前记下哪些是展开的，重绘后原样恢复。

**进行中的进度条目不再落盘。** 流式期间进度每 250 毫秒刷新一次，原来每次都要写一遍设置；结束时仍会正常保存。

### v1.6.25 · 收流不再卡死

长回包（尤其是候选线索那几步）流式返回期间，整个面板会卡死、按钮点不动。原因不在模型也不在网络，在插件自己：**每收到一小块内容，都要把已累积的全文从头重新丈量一遍字节，再把整份编译报告重拼一次写进 DOM。** 上千小块 × 数万字，开销是平方级的，手机主线程一口气都喘不上。

- **字节计数改成增量**：只丈量新追加的那一段。最终数值与逐块全量丈量完全相同（测试逐字比对通过），实测约 12 倍提速。
- **界面刷新限流**：流式期间最多每 250 毫秒刷新一次；首块、结束与出错仍立即上报，进度不会丢。

纯性能改动，不改任何行为、不动任何契约。

### v1.6.24 · 候选线索减负

编译第 4 步（候选线索）过去把 **28 条硬约束**全压给模型，写歪任何一条就整批作废、重来一次、再烧一次调用。这一版把凡是插件自己能算、能修、能校的，全部从提示词里搬进代码。

**提示词 28 条 → 5 条**（约 1180 字 → 450 字），只留真正需要判断力的部分：写出一句落在场景里、能察觉不对劲却读不出结论的迹象。

**下列各项改由代码执行，模型不必再背：**

- 层与档位一律按 assignment 强制校正，不再因为「擅自改变所属层或档位」废掉整批；
- `allowed_claim_ids` 按该条的 `eligible_claim_ids` 过滤，并按 `strength_cap` 截断；空了就是空数组；
- `nature` 按档位与 `clue_strength` 收到最软的一档；
- probe 的 `logic` 在只有一个 phrase 时自动收成 `any`，`hit_threshold` 本地夹回 `1..groups.length`；空 group、重复 phrase 一律剔除；
- 双花括号酒馆宏从 `surface` 与 `anchor_text` 剥除；
- 缺失的 `variant_id`、`anchor_text`、`exclude` 本地补齐，未知键剪除；
- ID 没对上时按顺序认领，不再「本步漏掉候选」全批丢弃；
- 本批少交几条时保住已成型的部分入库，缺的可用「补充候选」补回。

**没有放宽任何秘密边界。** 命题过滤只会更严（非 eligible 一律剔除）、力度只会更低、证据性质只会更软。所有本地修正都会写进编译报告，你能看见改了什么。

回包因此变短，单次编译费用也会下来一截。

### v1.6.23 · 运行闸收口

v1.6.9 给编译航道装过的三档判决，这一版补给运行航道。

在这之前，运行期的裁定安检只有一档：模型 JSON 写歪一个字，和模型想越过秘密边界，都是整轮作废、白烧一次调用、红字还看不懂。但那道闸里五十项检查，真正在守秘密的只有约十二项，其余全是形状债。

这一版在硬闸前面加了一层本地收口，只处理「模型把话说歪了」：

- **未知键剪除**：模型顺手多写一个 `reason` 或 `note` 不再让整轮报「字段非法」；未知键本来就没有授权，删掉只会更窄；
- **boundary_policy 按认知收口**：角色对该层不知情或持假记忆时，六档里只有 `honest_by_awareness` 合法，插件直接收到这一档——这正是 `safeBoundaryForLayer` 早就在用的安全默认值；
- **behavior_ref 冷却项丢弃**：调度 payload 一直把整个行为池当合法项发出，却从不发冷却表；越界、重复、冷却中的一律丢掉，行为提示是可选装饰，丢掉只会更素；
- **focus_layer 自动对齐**：投了哪张牌，focus 就是哪层，这个值百分之百可推导，不再要求模型手动同步两个字段；
- **action 本地推导**：`action` 只是个标签，不守任何秘密边界——牌能不能投由白名单硬闸决定。不再让模型抄一份插件自己就能算出来的答案；
- **投放三元组补齐或整组清空**：缺牌号一律清空成暂缓；有牌号缺变体时取该牌已过安检的第一个安全变体，缺时机时补最软的 `scene_permitting`；
- **压力与条件复核容错**：越界压力值夹回 0–10 并去重，越权或重复的条件复核直接丢弃（该条件保持原状，等于没复核），不再为一个记账数字废掉整轮。

**没有放宽任何秘密边界。** 线索白名单、stage_plan 许可、力度上限、性质限制、阶段许可、entry 因果闸、min_gap、override 白名单与目标越权，全部原样留在原处；收口层修完之后，这些硬闸仍会逐条复查一遍。收口层本身即使判断错了，也兜得住。

不增加 API 调用，不改秘密结构，不动已锁定的故事线。本地发生过收口时会写一条 `runtime_local_coerce` 审计。

### v1.6.18 · 宽口编译器

这一版把“模型必须像同一个程序员那样写 JSON”改成“模型负责故事判断，小萤火负责翻译模型方言”，让普通用户更换渠道或模型时不必自己看技术报错：

- 第二步会本地识别常见的蛇形/驼峰字段、中文或英文层名与档位名、`result/data/output` 外壳、条件字典、阶段字典和扁平阶段列表，并统一收成 Luciole 的内部格式；
- 模型只交回 conditions、漏写整张 stage_plans 时，插件会按每个条件已经明确写出的 target 接齐六档；缺少编号、`sticky`、空的早期门和安全空数组也由本地补齐，不追加 API 调用；
- 条件的目标只在“阶段计划中恰有唯一引用”时反推；同义字段互相冲突、多项逻辑含义不明、未知条件引用或真正没有因果条件时仍停止，不替 God 猜故事；
- 第一、三步和候选批的顶层也可接住常见外壳及驼峰字段，不再因 `initialPublicAnchor`、`personaSafe`、`candidateClues` 一类等价写法整步作废；
- 连接与报错台会显示“本地兼容收口 N 项”及人话修复记录。用户通常只会看到编译继续前进；需要排查时才展开技术详情；
- 秘密许可、最早揭示档位、跨层引用、越闸范围、宏注入和演员可见泄密安检均未放宽。放宽的是通信格式，不是剧情边界。

v1.6.17 或更早留下的 `1 / N` 草稿可以直接点“继续编译”；已完成的真相命题不会重跑。

### v1.6.17 · 干净编译航道

这一版根据同一 Fable 渠道“普通正文正常、短 JSON 实弹正常、完整编译断流”的对照结果，收窄并校准了连接配置编译航道：

- 编译调用只沿用连接配置中的 API 来源、地址、密钥与模型，不再继承聊天预设的思考强度、verbosity、停止词或其他生成参数；运行期连接仍保留原有预设行为；
- 报错台把“首个空流事件”和“首段有效文字”分开计时，不再把只有角色标记或状态的空包显示成模型已经开始输出；
- 编译记录新增流事件总数、有效/空事件数、最后事件时间、请求文本体积、请求输出上限及预设隔离状态；断流后可以直接判断是空包后中断、有效文字中途断开，还是完全没有建立流；
- `Load failed` 若发生在已经收到响应头或空事件之后，不再误报成地址、密钥或网络从未连接；
- 没有增加模型调用，也没有改变秘密结构、因果闸、安检法条或已有草稿。

### v1.6.16 · 宽口安检

这一版放宽的是可以由插件证明“修前修后含义相同”的格式口，不放宽秘密边界：

- `initial_public_anchor` 缺失或超长时，插件只从已经存在的公开版本与公开素材中选一条完整短句补齐，不读取隐藏答案、不截半句话，也不追加 API 调用；
- 人物画像中的隐瞒方式、行为池、暴露反应与主观锚点若只是不合长度或数量契约，会用不含剧情事实的完整安全模板替换或按整项收束，不再让一处格式病拦住整份故事；
- 同一个因果判定被模型复用于不同洋葱层或阶段时，插件会复制成多把谓词完全相同、目标标签各自正确的条件钥匙，并只重绑对应入口；未知条件、相互冲突的逻辑、缺失的真实因果门仍然硬拦；
- 运行期优先复核当前各层的下一扇门，避免复制后的备用条件挤占最多 12 条的 God 复核窗口；
- 已经编译完成但卡在这三类红字的草稿，安装新版后点“重新校验 JSON”即可本地修复，无需重新编译或再次付费。

越层线索、隐藏答案外泄、未知条件引用、越闸目标越权和真正缺少进入条件，仍然不会被自动猜测或放行。

### v1.6.15 · 因果条件柔性契约

这一版修复第二步已经交回完整因果结构，却只因 `condition.spec` 使用同义字段而整步失败的问题：

- 编译提示与 Schema 现在明确把 `kind` 和 `spec` 绑在一起：`evidence → clue_ids + logic`、`keyword_event → aliases + logic`、`relation/world_event → text`，并特别说明输入池 `evidence_candidate_ids` 在输出时必须改名为 `clue_ids`；
- 常见的无损字段变体由插件本地收成唯一格式，例如 `evidence_candidate_ids/candidate_ids → clue_ids`、`keywords/wake_aliases → aliases`、`condition/description/relation → text`，以及 `and/or/任一/全部 → all/any`；单项列表缺少 logic 时，本地使用与 all 完全等价的 any；
- 只删除已经能够证明不改变真值的通信格式差异，不重新解释模型的故事。两段文字互相矛盾、多项条件缺少 all/any、未知 threshold 或跨层引用等会改变因果的内容仍然硬拦；
- v1.6.14 留下的 `1 / 5` 草稿会继续保留。安装新版后点“继续编译”，只重跑第二步，不重复收费重做已经完成的真相命题。

### v1.6.14 · 角色世界书专域

Luciole 的世界书管辖范围现在固定为当前角色自身绑定的两类资料：

### v1.6.13 · 本地等价容错

这一版修复轻量模型把单短语探针写成 `all` 后被整卷拒收，以及环境预算提醒被误译为“God 漏交素材盘”的问题：

- 单个 phrase 的 `all` 与 `any` 在逻辑上完全等价。编译预览和 AI 监督运行期都会在本地把它规范为 `any`，不改线索文字、确认阈值或任何剧情事实，也不增加 API 调用；真正缺词、越权或泄密的内容仍会照常硬拦；
- 编译台、候选补库器和守幕人提示词同步写明这条格式规则，先减少模型犯错，再由本地兜住枚举笔误；
- “有资料因整段预算未送入 God”现在会准确显示为取材预算提醒，不再误称整个环境素材盘缺失。真正缺少素材盘仍是红色阻塞；黄色预算提醒不阻止锁定；
- v1.6.12 已经跑完、只卡在截图这类 `all组至少2词` 的草稿，安装新版后恢复原预览并点“重新校验 JSON”即可本地放行，无需重新调用 God。

### v1.6.12 · 故事环境取材层

这一版让编译 God 真正先读角色卡与世界书，再把作者锁定的秘密埋进这张卡自己的环境里，而不是套用一组通用悬疑道具：

- 编译前从当前单人卡或群聊在场角色读取场景、人物设定、开场、性格与示例对话，同时读取用户人设、世界观安全备注和当前角色的主世界书与卡内嵌世界书；
- 故事原料只在第三步发送一次。God 将其压成带真实出处的“环境素材盘”：时代、地点、机构、习俗、物件、流程、关系、氛围与不可冲突项；后续小批线索只携带这份短素材盘，不反复重发整本世界书，也不增加 API 调用次数；
- 真相与环境严格分工：`source_secret` 决定真相是什么，角色卡和世界书决定真相藏在哪里、通过什么证据载体和生活流程被发现；环境素材盘不得夹带未公开答案，也不能凭空伪造卡外出处；
- 智能候选、均匀种子、候选补库和 AI 监督运行期全部接收同一份已锁定环境素材盘，避免忽然出现不合时代的监控、陌生机构、现代手续或卡外关系；
- 作者预览会用人话显示 God 读取了多少段角色资料、多少本及多少条世界书，并可展开查看环境骨架与原始来源。盲玩模式只显示数量，不展示内容；
- 过长资料继续按整段预算取舍，永不截成可能改变含义的半句话。旧版已经锁定的故事线可原样运行；要获得环境取材能力，需要用 v1.6.12 新编译一条线。

### v1.6.11 · 洋葱层单向承接

这一版修正“跨层引用一律拒绝”造成的假阳性：动机层和情感真相层本来就可能建立在已经公开的事实之上，不应被当成提前泄密。

- 同层命题照常使用；更深层线索可以承接较浅层命题，但运行期会等到该浅层命题确实交付后才允许候选入场；
- 浅层线索仍不能反向引用更深层命题。若模型只是误挂了一个正文并未使用的深层许可，编译器会本地摘除；正文真的携带深层答案时仍然硬拦；
- 新编译时，每一条候选只会看到“本层且已经到达当前档位”的合法命题清单，减少 Flash 等轻量模型选错命题；
- v1.6.10 已经完成的草稿可在恢复预览后重新校验：合法的深层承接会直接放行，不必重新调用 God。

### v1.6.10 · 候选批稳定续跑

这一版针对候选线索步骤偶发“只思考、不交正文”或长 JSON 截断：

- 智能调度候选从每批 10 条收缩为每批 5 条；每一小批完成就保存检查点，失败只重跑尚未完成的小批，不重做前三步骨架；
- v1.6.9 已保存的 10 条一批草稿会按实际已有候选数重新计算进度，可直接续跑，不会重复生成或丢失旧草稿；
- 若兼容接口把一个完整、可解析的 JSON 错放进 `reasoning_content`，编译台会在本地接管并继续走严格 Schema 与安检；不完整思考仍然拒收，也不会把模型思考交给演员；
- 编译短步骤明确要求第一字符直接输出 `{`，减少轻量模型把正文预算耗在解释和过程上的概率。

### v1.6.9 · 编译法条同步与分工铺路

这一版解决“模型按提示交卷，安检却按另一套法条阅卷”的自锁，并真正缩短前期等待：

- 短词探针、`nature × 阶段/力度`、命题许可上限和人物画像长度已经同时写进编译提示与本地安检；
- 最终安检改成三档判决：能证明等价的格式债在本地修正，不追加 API 调用；单颗坏掉的备用候选在不影响因果闸且剩余数量足够时单独隔离；涉及秘密越权、均匀顺序、独占因果条件或旅程数量不足时继续硬拦；
- 探针已有三个独立语义槽时才把短词阈值抬到 3；不足三槽会换成演员正文中确实存在的完整短语，不制造永远无法交付的死探针；
- 线索力度超限只会在删除多余许可后正文仍能通过指纹复扫时自动收回；画像超长使用完整安全模板整项替换，绝不截半句话伪装合格；
- 编译面板可勾选“候选线索与均匀种子交给运行模型铺路”：前三步骨架仍走编译模型，内容批与补库可交给 Flash 等利落轻量模型；关闭后仍可全程使用骨架模型；
- 智能调度不再强迫所有用户预付 20% 备用候选，需要备用时再点“补充候选”；短秘密最多拆 6 个命题、中等秘密最多 10 个、长秘密最多 18 个，每个命题优先只保留 1–3 个稳定指纹；
- 新编译无论选择连接配置、当前连接还是独立 API，都走可续传的短步骤；失败仍只重试未完成步骤，不会静默追加收费修复调用。

作者预览会单独列出“本地修正记录”和“隔离记录”；盲玩只显示数量，不展示未来内容。

### v1.6.8 · 酒馆生态适配层

这一版先正骨，不继续给编译流程加功能：

- 演员可见的公开层、画像、线索、种子与当程光禁止残留任何未知 `{{...}}` 酒馆宏。`{{char}}` / `{{user}}` 会先由 Luciole 本地替成真实名字；其他双花括号在编译安检、当程光安检和最终注入前任一处命中，都会整包拦下，防止酒馆在安检后宏展开造成二次注入；
- 每个聊天的帷幕、流水、草稿与进度改存 `chatMetadata`。v1.4 / v1.5 / v1.6 旧全局账本会自动复制进当前聊天，确认元数据保存成功后才清旧副本；跨聊天仍在编译的草稿只进入临时搬运箱，不会串线；
- 世界书安检改走酒馆公开入口并如实列出读取结果；自 v1.6.14 起，管辖范围收窄为角色主书与角色卡内嵌书，其他来源不再扫描；
- 最低支持 SillyTavern 1.14。1.14–1.17 标为兼容适配，1.18+ 标为完整适配；Connection Profile 不再靠读取函数源码猜密钥能力，而以一次真正的 JSON 航道请求为准，结果留在面板；
- 公开唤醒仍只扫描玩家刚发出的消息，演员回复不会反向唤醒下一轮。

这轮没有执行编译瘦身；调用次数和现有五步/多步草稿均保持 v1.6.7 行为。

### v1.6.7 · 推理正文分流与第二步瘦身

针对推理模型真流式持续回传数万字节、却在正文开始前耗完本轮输出的情况：

- 酒馆连接配置与独立 API 现在分别累计“思考内容”和“正文内容”；诊断台会显示两者各自的字节数，不再把三万字节内心戏误报成正文；
- 流式正常结束但正文仍为零时，报错改为“模型只返回了思考过程”，并继续保留已经完成的草稿步骤；
- 智能调度第2步只负责因果条件和六档阶段门，不再要求模型把全部候选编号一次性分进所有层×档；
- 候选编号改由插件本地唯一分配。模型点名用于 evidence condition 的候选会优先放在对应闸门之前，其余候选按命题层、阶段权重与每格容量均匀排布；最终仍由原有引用、阶段、许可和数量校验复核；
- 这次瘦身不增加调用次数、不删除安全字段，也不改变编译总步数。v1.6.6 留下的 `1 / 5` 等分段草稿可直接点“继续编译”，已经完成的命题步骤不会重做。

单纯提高 `max_tokens` 不能保证推理模型留下正文口粮。若仍出现“思考有字节、正文 0 字节”，可直接切换非推理编译配置后续跑同一草稿。

### v1.6.6 · 酒馆连接配置真流式

强模型在后台思考超过约 60 秒时，“跟随酒馆当前连接”的 raw / quiet 调用可能尚未返回正文，就先被云酒馆门口的反向代理切成 `504`。单纯把 Luciole 的客户端等待时间改长，不能延长反代的等待时间。

v1.6.6 新增第三种模型航道“连接配置 · 真流式”：

- 直接使用酒馆官方 `ConnectionManagerRequestService`，按你在“连接管理器”里保存的 Connection Profile 发起请求；
- `stream: true` 从模型思考阶段开始逐块接收，插件在本地拼回完整 JSON；思考内容只用于保持连接与诊断，不会交给演员；
- 编译仍保留分段步骤与草稿检查点，每完成一步立即保存，中断后只重试失败步骤；
- 如果某条配置没有真正交出流式生成器，Luciole 会明确报“没有真流式”，不会偷偷改走整包请求，也不会自动发起第二次收费调用；
- 编译连接测试给强模型最多 120 秒和 256 个输出 token，避免推理 token 把“通”挤没；正式编译仍使用 500 秒总闸；
- 同一个安装包按能力探测工作，不提高最低版本：SillyTavern 1.14–1.18 均可使用；服务不存在、连接管理器被停用或配置不受支持时，面板会说明原因，原有“当前连接 · 兼容”和“独立 API”仍可选；
- SillyTavern 1.18+ 能按 Connection Profile 携带其中保存的 `secret-id`。1.14–1.17 的真流式服务可能沿用对应提供商当前选中的密钥，面板会提示先测试；Luciole 本身不读取酒馆密钥。

升级不会改写旧设置。原本选择“跟随酒馆”的用户仍停在兼容航道，只有主动选择“连接配置 · 真流式”并指定配置后才切换。

### v1.6.5 · 当前连接兼容航道

部分酒馆当前连接会在 `generateRaw + jsonSchema` 请求进入模型前直接返回 `Bad Request` 或 `Service Unavailable`。v1.6.5 不再向兼容航道发送原生 Schema 参数：

- JSON Schema 仍完整写在每个短步骤的固定提示中，并由插件本地逐字段验收；取消的是上游不兼容的请求参数，不是安全契约；
- 正式编译先尝试不带 Schema 的 `generateRaw`，保持无聊天上下文的干净输入；
- 若 raw 航道发生请求级拒绝，立即自动切到 `generateQuietPrompt` 短步骤；本页会话的后续步骤与断点续跑直接沿用兼容航道，不再反复撞 raw；
- “测试编译航道”与正式编译现在走完全相同的路线；诊断台会明确显示“原始短调用”或“原始航道被拒后自动切换”；
- v1.6.4 的失败草稿可以原地续跑，已经成功保存的步骤不会重做。

若 raw 的首次请求被拒后 quiet 兼容调用成功，本次只会多一次未进入正文生成的失败请求；插件不会对已收到正文的调用做静默重试。

### v1.6.4 · 酒馆当前连接分段编译

针对“跟随酒馆当前连接”在强模型上等待约 50 秒后只得到空内容、截断文本或不完整 JSON 的情况：

- 编译优先使用酒馆官方 `generateRaw`，不再携带旧聊天正文与角色扮演上下文；不兼容时由 v1.6.5 的兼容航道接管；
- 每个短步骤的提示词都携带严格 JSON Schema，回包继续由插件本地解析和校验；
- 一次大编译拆成“真相命题 → 因果结构 → 安全外壳 → 内容小批”；智能调度每批最多 8 条候选，均匀散落每批最多 25 条种子；
- 每完成一步立即落入聊天草稿。中途断网、刷新或回包不完整后，点“继续编译”只重跑失败步骤，不重收已经完成的步骤；
- v1.6.3 留下的 `0 / 1` 空失败草稿会自动升级成分段检查点，不用重新填写表单；
- 报错台会显示实际调用路线，草稿进度统一显示为“步骤”。

跟随酒馆当前连接会以多次短调用换取可续跑与完整回包：AI监督通常 4 次；智能调度为 `3 + 向上取整(候选数 ÷ 8)` 次；均匀散落为 `3 + 向上取整(线索数 ÷ 25)` 次。独立 API 仍走 v1.6.3 的 SSE 流式航道，不改成这套多步调用。

### v1.6.3 · 流式编译与草稿续传

针对强模型编译时首包慢、JSON 大而触发 `504 Gateway Timeout` 的情况：

- 独立 OpenAI 兼容 API 的所有编译调用默认使用 `stream: true`，插件持续读取 SSE 数据块并在本地拼回完整 JSON；
- 编译总闸独立为 500 秒，运行期仍是 20 秒；独立 API 编译请求的 `max_tokens` 明确不少于 8000；
- 诊断台会记录流式/整包传输、收到响应头、首个数据块、总耗时与中断前字节数；
- 每个完整批次一通过结构检查就立即写入聊天草稿，状态为 compiling / partial / ready / failed；
- 刷新页面或后续批次断网后，可用“草稿检查点”继续；已经完成的批次不会重新收费生成；
- 长编译任务绑定发起它的聊天；途中切换聊天，草稿与最终结果仍只写回原聊天；
- 不会在流式失败后静默发起第二次普通请求，避免同一次编译重复计费。

客户端等待 500 秒不能改写中转站自身的绝对超时。如果网关在第一块流数据出现前就主动返回 504，面板会如实显示；当前批需要手动重试。跟随酒馆当前连接没有底层 SSE 读取钩子，因此从 v1.6.4 起使用短步骤与逐步检查点处理。

### v1.6.1 · 编译台创作权限

编译台现在以“受约束的谜局设计师”工作，而不是把秘密压缩成几句摘要：

- 核心真相、既定动机、玩家选择和角色卡约束仍然锁死；
- 可以在不冲突的空白处设计记录、票据、时间差、物理痕迹、流程异常、通讯残片、旁观者片段、误判与传闻；
- 同一条真相可以拥有多条不同场景、载体和视角的证据路径；
- `candidate_target` 是候选线索数，不是秘密命题数，编译模型必须精确交齐；
- 秘密指纹必须排除角色卡与用户人设中本来就公开的人名、职业、关系、地点和常用物件，减少误报。

创造权只用于丰富“怎样发现”，无权改写“真相是什么”。

### v1.6.2 · 连接与报错台

God 双航道下方新增常驻诊断窗口：

- 可分别测试“编译航道”和“运行航道”，也可在保存方案前测试当前填写；
- 连接中、成功、安检拦截、HTTP 错误、空回包、输出截断、超时和运行期拒收都会留在面板里；
- 显示调用航道、模型、脱敏后的目标地址、时间与耗时，最近保留 20 条，直到用户手动清空；
- `400 / 401 / 403 / 404 / 429 / 5xx` 会翻译成可操作的人话，上游原始说明放在折叠详情中；
- API Key、Bearer 凭据与 URL 查询令牌会在写入记录前清除；盲玩模式不会把未来内容写进报错详情。

短暂 toast 仍作为即时提醒，但不再承担唯一报错入口。

## 安装

最低支持 SillyTavern 1.14.0；1.18+ 可使用完整的 Connection Profile 密钥转发能力。

把整个 `luciole` 文件夹放到：

`SillyTavern/data/default-user/extensions/luciole/`

然后重启 SillyTavern。也可以把 `luciole` 文件夹原样上传到 GitHub，再从 SillyTavern 的扩展安装入口使用仓库地址安装。

运行插件只需要这四项：

- `manifest.json`
- `index.js`
- `style.css`
- `README.md`

`tests/` 不参与日常运行，但建议一并上传，方便以后升级时确认旧能力没有坏。

## 三种运行方式

### AI 监督 · 随境生光

适合不想预设故事终点、希望线索跟着剧情自然生长的长线 RP。

- 你只设置“每隔几轮监督一次”和线索力度；
- 编译台只建立真相骨架，不预写全部线索；
- 每到监督窗口，守幕人读取近期剧情和有限真值切片，决定 hold、推进或临场起草一条证据；
- 运行期间会调用模型；默认每个间隔至多一次；
- 安全标记为“动态候选级”：临时证据仍要过 Schema、命题许可、阶段、性质和指纹安检，但不能宣称语义上绝对无泄漏。

### 智能调度 · 循迹择光（推荐）

适合“前期愿意用强模型，之后想用便宜模型慢慢玩”。

- 你设置预计总轮数、调度间隔和线索力度；
- 骨架模型先锁定命题、因果门和安全外壳，铺路模型再建立候选库；默认可让运行模型兼任铺路，也可关闭分工、全程跟随骨架模型；
- 运行时模型只从合法 `clue_id / variant_id` 中选牌，不能临场写新线索；
- 骨架模型和铺路/运行模型可以分开：例如骨架使用能力强但落笔利落的模型，铺路与调度使用便宜的 Flash；
- 面板会用人话显示候选库“剩余 N 条 / 共 N 条”；快用完时可点“补充候选”，确认后由铺路模型新增 1–40 条，旧真相、旧候选和历史账本保持锁定；
- 安全标记为“封闭白名单级”。

例：预计玩 500 轮、每 10 轮调度一次，预计有 50 个窗口，首次编译 50 条候选。若实际游玩中需要更多换牌空间，再用“补充候选”按需加库。

### 均匀散落 · 星雨成行

适合节奏必须可计算、运行时希望完全不再花 God 调用的钱。

- 你设置预计总轮数、投放间隔和线索力度；
- 线索数 = `floor(预计总轮数 / 投放间隔)`；
- 编译台开局拆好有序线索；独立 API 每批最多 100 条，跟随酒馆当前连接每个内容步骤最多 25 条；全部步骤通过后才会一起激活；
- 运行时严格按顺序本地投放，God 调用数恒为 0；
- 某条漏演时不会跳到下一条，真正交付后下一投放点会滑动顺延；
- 安全标记为“封闭白名单级”。

例：预计玩 500 轮、每 5 轮一条，会拆成 100 条线索；第 5、10、15……轮依次投放。

## 什么叫“一轮”

一次玩家行动加一次角色回复，算 1 个完整 RP 轮。

- 激活 Luciole 之前的聊天历史不计入新线的轮数；
- 同一楼 swipe / 重抽不增加轮数；
- 生成失败不增加轮数；
- 删除楼层时，轮时钟、已交付线索、阶段和均匀游标会随事务一起回滚。

## 线索力度

- **轻柔留痕**：每次最多携带 1 个已经合资格的信息单元，只用观察或传闻；
- **标准推进**：每次最多 2 个信息单元；
- **清晰证据**：每次最多 3 个信息单元，条件成熟后可以出现事实或陈述。

力度只控制本轮信息密度，不能越过命题最早阶段、因果条件、洋葱层或越闸上限。选择“清晰证据”不会让第 10 轮直接得到第 500 轮的动机结局。

## 公开关键词怎样触发

编译台会从公开表层提取一组 `wake_aliases`，例如已经公开的人名、地点或话题。它们不是秘密答案，也不是“说中一个词就掉线索”的机械机关。

默认行为：

- 只扫描玩家刚发出的新消息，不扫描演员自己的回复；
- 命中后只记一个本地“值得留意”标记，等下一个正常监督/调度窗口参考；
- 不会因此偷偷多调用一次 API。

若你手动开启“事件唤醒”：

- 玩家命中公开话题时，可以把下一次 AI 监督或智能调度提前；
- 提前调用后，原来的时间点不会再重复调用；下一窗口从本次重新按间隔计算；
- 均匀散落永远不会因关键词调用模型。它只会保留“催促剧情”入口。

## God 分工航道

面板里可分别设置：

- **骨架编译模型**：负责命题、因果门和安全外壳，建议使用能力较强、但不会长时间只思考不落笔的非推理模型；
- **运行模型**：负责 AI 监督和智能调度。可跟随骨架模型，也可单独选择另一份酒馆连接配置、当前连接兼容航道或独立轻量 API；
- **铺路线索开关**：开启时，智能候选批、均匀种子批和候选补库交给运行模型；关闭时这些内容仍由骨架模型完成。

三种航道的区别：

- **连接配置 · 真流式（推荐给强编译模型）**：从酒馆“连接管理器”读取配置，由酒馆代发并持续回流；支持 Chat Completion 与 Text Completion 配置；
- **当前连接 · 兼容**：优先使用 `generateRaw`，遭遇请求级不兼容时改用带明确数据边界的 `generateQuietPrompt`；这两种后台调用都不是可读取的真流式，云端 60 秒反代仍可能切断强模型；
- **独立 API**：Luciole 自己保存地址、模型名和 Key，直接调用 OpenAI 兼容 `/chat/completions`；编译请求使用 SSE 流式。

固定 system 规则与 JSON data payload 始终分开发送。Connection Profile 和独立 API 都不会携带旧聊天正文；当前连接兼容航道的 quiet 回退会经过酒馆上下文调用，但资料被 BEGIN/END 数据边界包住。

运行期等待上限可在面板设置为 20–600 秒，默认 120 秒。超时会安全放行当前正文，迟到回包永久丢弃；到期窗口不会被误消费，下一轮仍会继续尝试。插件不会在同一轮失败后静默追加收费调用。

## 第一次点灯

1. 在角色卡、用户人设和当前角色绑定的主世界书/卡内嵌世界书中移除秘密答案，只保留公开表层。编译前先看“角色世界书”是否核对成功。
2. 打开 Luciole，先配置骨架编译模型。强模型优先选“连接配置 · 真流式”：先在酒馆连接管理器建好配置，再回 Luciole 下拉选择并点“测试编译航道”。若要用 Flash 铺路，配置运行模型并勾选“候选线索与均匀种子交给运行模型铺路”。
3. 填线名、完整秘密，选择作者/盲玩、三种运行方式、轮数、间隔和力度。
4. 点击“让 God 编译”。
5. 普通界面只显示人话，例如“已拆分线索 100 条”；作者可以展开人话线索预览。JSON 放在折叠的“开发者详情”里。
6. 若安检未过，页面先说明“哪类问题需要修”；`clue / claim / stage / probe` 等技术原因只在作者模式的折叠栏里。
7. 安检通过后点击“确认并锁定”。

每个聊天最多四条受保护线；同一时刻只有一条 FOCUS 负责推进，其余 STANDBY 仍穿知识边界，不会因为不推进就裸奔。

## 作者模式与盲玩模式

- **作者模式**：可以预览未来结构、展开开发者 JSON，并在探针拿不准时使用“确实交付 / 未交付撤销 / 稍后”三键仲裁。
- **盲玩模式**：只显示“拆分线索 N 条”、当前轮数、下一处理点和已经公开的账本；未来 surface、claims 和技术详情都不出现。

盲玩模式只是不在运行面板剧透。如果秘密本来就是玩家本人输入的，玩家当然已经知道它；真正的完全盲局需要主持人预编译内容包，或后续私人副本引擎。

## 事务与回滚

- 裁定先冻结，演员演出并由探针确认后，阶段、条件、披露、人物行为冷却与均匀游标才原子提交；
- 漏演不入账；同楼 swipe 沿用同一裁定，不会变成命运老虎机；
- 尾删和最新一楼重抽会自动整包回滚；
- 编辑更早历史时，Luciole 回滚到最早分叉点并提示重新推进；
- 事件流水只追加，回滚也是一笔新事务，不偷偷改写历史。

## v1.4 / v1.5 升级

- v1.5 的帷幕线会原地迁移成“智能调度”，保留 hidden/safe/control/runtime 四区、pending、谱系和事件流水；旧 `min_gap` 暂时沿用，面板标注“沿用旧版节奏”。

升级前仍建议备份 SillyTavern 数据。

## 已知边界

- 指纹安检是确定性近似，能挡稳定专名和词组，不能数学证明不存在语义暗示；AI 监督尤其需要诚实理解为“动态候选级”。
- 插件只会逐本核查当前角色的主世界书与卡内嵌世界书，并如实列出漏读项；聊天、Persona、全局、角色附加书、旧聊天正文、预设私有注入和其他插件通道均不属于 Luciole 的管辖范围。建议在新聊天启用秘密线。
- Luciole 能封住自己交给 `setExtensionPrompt` 的演员包宏，但无法替其他扩展核查它们各自的注入文本。
- 均匀散落不做运行期语义理解。若硬证据突然拍脸，请使用“催促剧情”提前下一条；作者模式还可做事实层仲裁，但不会顺带打开动机与情感层。
- 单条秘密目前最多 2000 字；均匀序列最多 1000 条；智能调度候选库总量最多 160 条，单次补库最多 40 条。
- Connection Profile 真流式依赖上游与中转站真的保留 SSE；若中转站先缓存完整内容再吐回，Luciole 会在测试台显示没有及时收到数据块，反代仍可能 504。
- SillyTavern 1.14–1.17 可能不把 Connection Profile 的 `secret-id` 传给扩展请求；请保证对应提供商当前密钥可用并先点“测试编译航道”。1.18+ 才能稳定按配置密钥标识代发。
- 独立 API Key 保存在 SillyTavern 扩展设置中，共用设备请自行留意。
