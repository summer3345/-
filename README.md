# Luciole v1.3.1（曾用名：小萤火）

叙事节奏控制器：把长线从模型手里收走——机器管节奏，模型管演技。
秘密不写在卡里，写进梯子；模型每轮只见当前一颗碎片，想剧透都没有料。

## 安装

方式一（推荐）：传到 GitHub 仓库，ST 扩展面板「Install extension」填仓库地址。
方式二：把 `luciole` 整个文件夹放进
`SillyTavern/data/default-user/extensions/luciole/`，重启 ST。

## 使用三步

1. **搬家**：把角色卡里的秘密原句剪出来、删掉，卡里只留无害表层
   （如"她对旧案话题反应冷淡"）。
2. **种线**：点浮标开面板，填线名、终点备注（永不注入）、楼距，
   一行一颗碎片从早到晚排：
   `碎片内容 | 落地关键词 | 前置关键词 | 必`
   - 落地关键词：AI 正文出现其一即算"接住了"；留空 = 掉了即算落地
   - 前置关键词：近 30 楼正文或摘要里出现过才允许掉这颗；留空 = 无前置
   - 第四列写"必"= 注入时标注本轮必须出现
3. **跑戏**：插件自动按 楼距地板 → 上颗已落地 → 前置满足 →（可选）判读
   的顺序放行掉落。萤火点：暗 = 待掉，闪 = 已掉飘着，常亮 = 已落地。

## 判读开关

开启后每次掉落前多调一次当前 API，拿 双卡 + 世界观备注 + 摘要 + 近两楼正文
判断"此刻掉贴不贴"。判读失败自动放行（退回纯楼距模式），不会卡死。
不开判读 = 零额外 token。

## 纪律

ES5 全程；零全局补丁；只用官方 API（setExtensionPrompt / eventSource /
generateQuietPrompt）；per-chat 隔离；运行时不读卡、不读世界书
（判读的世界观走面板里的手填备注——自动读世界书条目留给 v1.1，
等确认线上 ST 版本的 context 暴露面再动）。

## 已知边界（v1 如实交代）

- 编辑已在跑的梯子时，旧进度按行号对齐保留——增删中间行会错位，建议只改文字
- 摘要读取兼容 ST 官方 summarize 扩展；预设自带的摘要判读模型看不见
  （但它在正文管线里，主模型看得见，不影响演出）
- 判读的 generateQuietPrompt 兼容了新旧两种签名，线上哪种能跑等实测

## v1.1.0 新增

**判读 API 方案制**：判读开启后可选「跟随酒馆当前连接」（零配置）或
「独立 API」。独立模式填 URL + Key + 模型名，保存为方案，多方案下拉切换，
一键测试连接。协议走 OpenAI 兼容格式——Claude 中转、Gemini openai 兼容
端点、各家中转站通用；URL 贴到 /v1 即可，自动补全 /chat/completions。
Key 明文存在 ST 设置里（与同类插件一致），共用设备请自行留意。

**楼层对表机制**：记账原则改为「掉落是台账，落地是推导态」。
- 删楼：掉落楼层戳比当前楼靠后的碎片自动撤回待掉，游标与楼距基准跟着倒带
- 重 roll / 编辑：落地状态从现存正文重新推导，roll 掉了关键词自动退回"飘着"
- 触发时机：每楼消息后、删楼/重roll/编辑事件、切聊天时，萤火自动对表
- 分支聊天是新 chatKey，梯子不跟随（每条分支各自种线）——v1.x 现状

## v1.4.0 —— 档二：编剧模式

- 种线时二选一：**耕田**（碎片自己写，萤火管节奏，零 API 门槛）/
  **编剧**（把剧情脉络交给萤火，光由她放）
- 编剧模式：user 是编剧，char 蒙眼。萤火持有脉络（绝密，永不注入），
  每到掉落窗口自己看戏、自己决定这一程光是什么——现场生成线索，
  记漏账、越漏越深、漏非撬
- 编剧线需要判读 API（跟随酒馆或独立方案均可）；API 失败关闸不放光
  （与耕田的失败放行相反：宁可不放，不放瞎光）
- 对表机制适配：编剧线的光长在生成那一刻的戏里，删楼倒带 = 直接收回
  （非归零重掉）；「收回上程光」手动可撤
- 已放的光进台账，卡片显示「已放 N 程光 · M 程落地」
- 远景（与江讨论中）：档三双蒙眼/上帝之眼——世界观交给插件而非酒馆，
  user 与 char 同为迷雾中人
